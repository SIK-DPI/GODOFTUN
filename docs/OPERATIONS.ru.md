# Эксплуатация — GODOFTUN V1.0.0

[English](OPERATIONS.md) · [فارسی](OPERATIONS.fa.md) · [简体中文](OPERATIONS.zh-CN.md) · [Русский](OPERATIONS.ru.md)

[Главная](../README.ru.md) · [Установка](INSTALLATION.ru.md) · [Настройка](CONFIGURATION.ru.md) · [Cloudflare](CLOUDFLARE.ru.md) · [Диагностика](TROUBLESHOOTING.ru.md) · [Безопасность](SECURITY.ru.md)

Ниже приведены инструкции для ваших серверов, а не отчёт о проверенном развёртывании. Замените `TUNNEL_ID` и при необходимости `CUSTOMER_ID` настоящими идентификаторами. Команды управления требуют root. Перед первым запуском прочитайте [Установку](INSTALLATION.ru.md), а перед общими изменениями или квотами — [Настройку](CONFIGURATION.ru.md).

## Выбор нужного туннеля

```bash
sudo godoftunctl list
sudo godoftunctl status TUNNEL_ID
sudo godoftunctl health TUNNEL_ID
sudo godoftunctl edit-show TUNNEL_ID
```

Отображаемое имя — не внутренний ID. Локальный сервис называется `godoftun@TUNNEL_ID`, настройки находятся в `/etc/godoftun/tunnels/TUNNEL_ID`, состояние учёта — в `/var/lib/godoftun/TUNNEL_ID`. В собственных скриптах указывайте ID явно. Если его нет, менеджер выбирает единственный туннель или предлагает выбрать из нескольких.

## Команды установщика

| Аргумент `bash ./GODOFTUN-V1.0.0.sh` | Действие |
|---|---|
| Без аргумента | Главное меню: зарубежная установка, установка в Иране, управление, перенос файла или обновление V1 |
| `preview` или `--preview` | Показ меню без root, сетевых проверок, установки и выдуманных текущих показателей |
| `foreign` или `egress` | Установка зарубежной стороны; нужен root |
| `iran` или `origin` | Установка иранской стороны; нужны root и зарубежный код сопряжения |
| `manage` | Управление существующими поддерживаемыми V1-туннелями; нужен root |
| `upgrade` | Обновление одной выбранной поддерживаемой установки V1; нужен root |
| `transfer-help` | Инструкции по переносу файла |

Установленная копия находится в `/opt/godoftun/share/godoftun-easy.sh`. Для обновления используйте заново скачанный и проверенный установщик нужного выпуска. Повторный запуск старой копии не скачивает новую версию.

## Полная таблица команд `godoftunctl`

Если не указано иное, формат — `sudo godoftunctl COMMAND TUNNEL_ID`. Для `list` ID не нужен; `help` показывает справку. Информационные команды сами по себе не подтверждают работу настоящего клиентского трафика.

| Команда | Назначение |
|---|---|
| `list` | Туннели на этом сервере |
| `status` | Подробное состояние сервиса systemd |
| `health` | Состояние, PID/перезапуски, ресурсы процесса, статистика текущего запуска и слушатели |
| `monitor` | Обновление состояния каждые две секунды; выход — Ctrl+C |
| `logs` | Последние 100 записей журнала и новые записи; выход — Ctrl+C |
| `start`, `stop`, `restart` | Изменение состояния только выбранного сервиса |
| `config` | Управляемая команда запуска; при обычной установке содержит путь к файлу токена, а не сам токен |
| `info` | Информация о клиентском endpoint и inbound |
| `ports` | Зарегистрированные порты, включая служебные резервы, а не только публичные клиентские порты |
| `peer-code` | Конфиденциальный установочный код сопряжения на зарубежной стороне |
| `test` | Проверка сервиса и настроенного TLS-пути; не сквозной тест приложения |
| `doctor`, `scan` | Один и тот же ограниченный диагностический инструмент; параметры ниже |
| `edit` | Полный редактор настроек |
| `edit-show` | Редактируемые настройки со скрытым токеном |
| `edit-ip` | Выбор и изменение иранского или зарубежного IP |
| `edit-ports` | Зарубежные HTTPS-порты на зарубежной стороне или входные порты по умолчанию в Иране |
| `edit-apply`, `apply-update` | Применение конфиденциального подписанного обновления редактора V1; это псевдонимы |
| `customers` | Меню клиентов на иранской стороне |
| `usage` | Квоты, записанный расход, остаток и состояние клиентов |
| `customer-add` | Отдельный клиентский вход и информация об endpoint |
| `customer-quota` | Изменение накопительного лимита клиента без сброса расхода |
| `customer-disable`, `customer-enable` | Изменение доступа с сохранением учётной записи и расхода |
| `customer-export` | Запись и показ JSON-файла клиентского endpoint |
| `customer-ports` | Изменение прямых входных портов клиента с сохранением расхода |
| `tunnel-quota` | Общий накопительный лимит всего туннеля |
| `delete` | Удаление одного туннеля после ввода его точного ID; см. раздел удаления |
| `help` | Справка по командам |

Команды существующего клиента принимают `CUSTOMER_ID` третьим позиционным аргументом; без него предложат выбрать клиента. Список портов и квота вводятся интерактивно, а не дополнительными недокументированными аргументами. Например:

```bash
sudo godoftunctl customer-export TUNNEL_ID CUSTOMER_ID
sudo godoftunctl customer-quota TUNNEL_ID CUSTOMER_ID
sudo godoftunctl customer-ports TUNNEL_ID CUSTOMER_ID
```

Операции квот/портов сохраняют изменения после ответов на вопросы. Не предполагается, что у каждой клиентской операции есть отдельное подтверждение `Apply?`, как в редакторе. Команд `customer-delete`, ежемесячного продления и сброса расхода нет. Перед выдачей квот прочитайте раздел учёта клиентов в [Настройке](CONFIGURATION.ru.md).

## Наблюдение и ограниченная диагностика

Начните с `status` и `health`. Health показывает статистику текущего запуска сервиса, а не старые сессии прошлого запуска. RSS в системных инструментах отличается от бюджета удерживаемых буферов. `usage` отмечает устаревшие/остановленные снимки; старый снимок — не текущее измерение. Статус `active` не доказывает работу аутентификации Xray, передачи данных или устойчивой скорости.

Следующие проверки не меняют настройки туннеля. Первая выполняется офлайн; остальные обращаются к настроенным либо явно указанным адресам:

```bash
sudo godoftunctl doctor TUNNEL_ID --offline
sudo godoftunctl doctor TUNNEL_ID --timeout 8
sudo godoftunctl doctor TUNNEL_ID --endpoints tunnel.example.com:443,tunnel.example.com:8443
sudo godoftunctl doctor TUNNEL_ID --output /root/godoftun-doctor.json
```

`tunnel.example.com` — пример для документации; заменяйте его только своими адресами или адресами, которые разрешено проверять. `doctor`/`scan` принимает не более 16 конкретных хостов/IP, не диапазоны. `--timeout` — 1–20 секунд, по умолчанию 8; ограничивается каждый этап и общее время проверки ядром. `--binary` — расширенный выбор подходящего исполняемого файла; по умолчанию `/usr/local/bin/godoftun`, не запускающий скрипт `run.sh`.

`--offline` проверяет локальную конфигурацию без сетевых запросов и не подтверждает связность. Успех онлайн требует новой аутентифицированной проверки несущего соединения; строгий ECH использует настоящее рукопожатие ядра с ECH. Даже `carrier-authenticated` не проверяет полезные данные конечного приложения и клиентские реквизиты. Код выхода 0 означает аутентифицированное соединение либо успешную офлайн-проверку настроек, 1 — неуспешный диагностический результат, 2 — ошибку конфигурации/отчёта.

`--output` создаёт приватный JSON-отчёт с удалением чувствительных данных и отказывается перезаписывать существующий файл или symlink. Для повторного запуска выбирайте новое имя. Всё равно просмотрите отчёт перед передачей. Сырые логи, `config`, `info`, `edit-show` и скриншоты могут раскрыть адреса, пути и эксплуатационные сведения. `peer-code`, файлы сопряжения, коды редактора и резервные копии конфиденциальны: не публикуйте их в issue. См. [Безопасность](SECURITY.ru.md) и [Диагностику](TROUBLESHOOTING.ru.md).

## Согласование изменений

Используйте `edit` на одной стороне и `edit-apply` на другой. Передавайте выданный код безопасно и вставляйте в приглашение программы, а не в shell-команду или публичное сообщение. Завершайте синхронизацию каждого общего изменения до следующего. Локальные ID на серверах могут отличаться: выбирайте настоящую пару, а не просто похожее отображаемое имя.

Коды действуют семь дней и проверяют предыдущее значение, идентификатор пары и противоположную роль. `apply-update` теперь вызывает тот же подписанный редактор, а не старый сырой механизм обновления. `peer-code` предназначен для первичной установки. Изменение домена/IP по-прежнему требует самостоятельного обновления DNS и клиентских устройств; уже выданные endpoint-файлы удалённо не обновляются. Подробности — в [Настройке](CONFIGURATION.ru.md).

## Перенос установщика при ограниченных загрузках

Полный установщик уже содержит обе архитектуры Linux. Копируйте проверенный файл с доверенной машины: для получения самого исполняемого файла Ирану не нужны Go или доступ к GitHub. Адреса ниже зарезервированы для документации; замените их адресами своих серверов.

С доверенной машины отправьте файл выпуска в Иран:

```bash
scp ./GODOFTUN-V1.0.0.sh root@203.0.113.20:/root/GODOFTUN-V1.0.0.sh
```

Либо выполните в Иране команду получения установленной копии с зарубежного сервера:

```bash
scp root@198.51.100.10:/opt/godoftun/share/godoftun-easy.sh /root/GODOFTUN-V1.0.0.sh
```

Используйте показанное имя только если установленная копия действительно является нужным установщиком V1.0.0. Проверьте ключ SSH-хоста и сравните SHA-256 полученного файла с доверенным оригиналом перед запуском:

```bash
sha256sum /root/GODOFTUN-V1.0.0.sh
sudo bash /root/GODOFTUN-V1.0.0.sh iran
```

Это офлайн-**доставка файла**, а не обещание полностью автономной установки: пакеты системы, DNS, проверка сертификатов и работающий путь Cloudflare могут требовать сети. Нужные зависимости должны быть доступны. Установщик может использовать действительный PEM CA bundle в `/etc/godoftun/tunnels/TUNNEL_ID/ca-bundle.pem` или общем `/etc/godoftun/ca-bundle.pem`; иначе он использует системный набор CA или пытается установить `ca-certificates`. Передавайте только публичные CA-сертификаты из доверенного источника, не закрытый ключ сервера. См. [Установку](INSTALLATION.ru.md).

## Обновление существующего V1

Обновление предназначено для зарегистрированной установки `GODOFTUN_V1_CF_WSS`, а не миграции с 3.x. Неподдерживаемые метаданные установок, несовместимые зарубежные режимы подключения или незарегистрированный исполняемый файл блокируют замену общего бинарного файла. Не удаляйте эти проверки и не выдавайте 3.x за V1 сменой метки.

1. Прочитайте результаты проверок нового выпуска. Сохраните прежний проверенный установщик и защищённые резервные копии; выделите окно обслуживания обеих сторон.
2. На каждом сервере запустите новый установщик с `upgrade` и выберите нужный локальный туннель. Выполните проверку DNS Cloudflare по запросу и внимательно подтвердите действие.
3. Повторите для всех существующих туннелей обоих серверов. Исполняемый файл и помощники общие, но каждая операция обновляет настройки и сервис только выбранного туннеля. Остальные сервисы автоматически не перезапускаются; при следующем запуске они используют общий новый файл.
4. Проверьте `status`, `test`, `doctor`, затем реальным клиентом проверьте отправку/приём, несколько портов, квоты и переподключение. Одни сервисные проверки не подтверждают сетевой маршрут.

```bash
sudo bash ./GODOFTUN-V1.0.0.sh upgrade
```

Поддерживаемые настройки, сертификаты, ID, квоты и расход сохраняются. Остановленный туннель остаётся остановленным. Если конфигурация учёта есть, а журнал расхода отсутствует, обновление останавливается вместо выдачи нового объёма. Для поддерживаемого старого V1 без учёта запрашивается начальная общая квота; измерение начинается с этого обновления, поскольку прошлый трафик восстановить нельзя.

## Откат, резервные копии и расход

Транзакции установки/обновления, изменения редактора и клиентские изменения сохраняют ограниченные своей областью копии под `/opt/godoftun/backups/`. Каждая операция печатает собственный путь. При сбое выполняется попытка вернуть изменённые файлы и прежнее состояние сервиса. Если безопасное восстановление подтвердить нельзя, затронутый сервис может быть остановлен до ручной проверки.

Это не взаимозаменяемые снимки всей системы. Откат редактора/клиентских настроек намеренно не возвращает старый журнал живого трафика, чтобы не возвращать уже израсходованные байты. Не копируйте старый `access-state.json` поверх работающего или более нового журнала. Повреждение, пропавшее состояние и отсутствие подтверждения настроек нужно расследовать. Удаление файлов учёта ради запуска сервиса лишает гарантии сохранения расхода.

Документированной команды `godoftunctl restore` или отката версии одной командой нет. По своему плану резервирования храните защищённые копии нужной конфигурации, текущего состояния учёта, соответствующего выпуска и сертификатных материалов. Согласованное ручное восстановление может потребовать остановить туннель и согласовать обе стороны. Используйте фактическую копию конкретной операции и её сообщение об ошибке, а не выдуманную универсальную команду. Копии содержат секреты и должны храниться приватно.

## Остановка, отключение клиента и удаление туннеля

Это разные действия:

- `stop` останавливает сервис туннеля, сохраняя установку, настройки и расход. `start` запускает его снова.
- `customer-disable` отключает учётную запись и доступ, сохраняя идентификатор, счётчики, квоту и зарегистрированные порты. `customer-enable` не сбрасывает расход и не обходит исчерпанную квоту.
- `delete` убирает целый выбранный туннель из управления. Это не удаление клиента и не деинсталляция всей программы.

Проверьте ID и выполняйте следующую команду только если действительно хотите удалить этот туннель:

```bash
sudo godoftunctl delete TUNNEL_ID
```

Менеджер просит набрать точный ID. Он останавливает и отключает сервис, перемещает конфигурацию и состояние в приватную копию `deleted-TUNNEL_ID-...` и убирает управляемый сайт Nginx только если на него не ссылается другой туннель. Проверяются конфигурация и перезагрузка Nginx; при ошибке выполняется попытка отката.

Общие исполняемые файлы, сам Nginx, другие туннели, сертификаты и правила firewall сохраняются. Проверьте неиспользуемые открытые порты вручную: удаление одного туннеля не означает, что безопасно закрыть все порты. Удаление на одном сервере не удаляет вторую сторону, DNS-записи или клиентские устройства. Сохранённая копия — восстанавливаемые данные, а не автоматическая функция возврата. Об оставшихся реквизитах читайте в [Безопасности](SECURITY.ru.md), об ошибках удаления/восстановления — в [Диагностике](TROUBLESHOOTING.ru.md).
