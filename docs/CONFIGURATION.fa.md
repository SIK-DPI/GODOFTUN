# تنظیمات — GODOFTUN V1.0.0

[English](CONFIGURATION.md) · [فارسی](CONFIGURATION.fa.md) · [简体中文](CONFIGURATION.zh-CN.md) · [Русский](CONFIGURATION.ru.md)

[صفحهٔ اصلی](../README.fa.md) · [نصب](INSTALLATION.fa.md) · [کلودفلر](CLOUDFLARE.fa.md) · [مدیریت](OPERATIONS.fa.md) · [عیب‌یابی](TROUBLESHOOTING.fa.md) · [امنیت](SECURITY.fa.md)

این نسخه فقط یک روش اتصال دارد: دامنهٔ خارج با پروکسی روشن کلودفلر روی WSS و ورودی مستقیم IP و پورت در ایران. ویرایشگر امکان انتخاب آروان، خارج بدون پروکسی، دامنهٔ ایران، HTTP/2 یا XHTTP را نمی‌دهد. تنظیم کلاینت و احراز هویت inbound، حساب کلودفلر و رکوردهای DNS بر عهدهٔ شماست.

## ورود به تنظیمات

به‌جای `TUNNEL_ID` شناسه‌ای را بگذارید که دستور `list` نشان می‌دهد. دستورها را روی سروری اجرا کنید که می‌خواهید تنظیماتش را ببینید یا تغییر دهید:

```bash
sudo godoftunctl list
sudo godoftunctl edit-show TUNNEL_ID
sudo godoftunctl edit TUNNEL_ID
```

`edit-show` تنظیمات ذخیره‌شده را نشان می‌دهد، نه سلامت زندهٔ اتصال؛ token مخفی می‌ماند. ویرایشگر مقدار قبلی و جدید را نشان می‌دهد و با پرسش `Apply? y/n` تأیید می‌گیرد؛ پاسخ پیش‌فرض `n` است. سرویس فعالِ مربوط به تغییر ممکن است دوباره راه‌اندازی شود، اما سرویس متوقف خودکار روشن نمی‌شود. به‌جای تغییر دستی `run.sh` و فایل‌های مشخصات، از همین منو استفاده کنید تا وابستگی تنظیمات، پورت‌ها و اطلاعات طرف مقابل بررسی شود.

## اتصال و مشخصات تونل

| تنظیم | کاربرد و محدودیت | محل اثر |
|---|---|---|
| نام نمایشی تونل | متن قابل نمایش تا ۱۲۰ بایت UTF-8، بدون `=`؛ شناسهٔ داخلی و هویت جفت‌شدن عوض نمی‌شود. | محلی |
| IPv4 سرور خارج | آدرس سرور اصلی برای مشخصات و بررسی‌ها؛ ایران همچنان به دامنهٔ پروکسی‌شده وصل می‌شود. پس از جابه‌جایی سرور، مقصد واقعی DNS را خودتان تغییر دهید. | مشترک |
| IPv4 سرور ایران | آدرس عمومی تحویلی به کاربران؛ دستگاه مشتری خودکار به‌روز نمی‌شود. | مشترک |
| دامنهٔ خارج | نامی مثل `tunnel.example.com`، بدون scheme، پورت یا مسیر؛ همهٔ آدرس‌های DNS باید بررسی پروکسی کلودفلر را پاس کنند. | مشترک |
| پورت‌های HTTPS خارج | پورت‌های غیرتکراری از `443,2053,2083,2087,2096,8443`؛ پیشنهاد نصب `443` است. | مشترک |
| پورت‌های ورودی ایران | پورت TCP حساب پیش‌فرض؛ هر مشتری دیگر تنظیم پورت خودش را دارد. پورت اشغال یا رزروشده پذیرفته نمی‌شود. | مشخصات مشترک؛ تغییر ورودی در ایران |
| مسیر WebSocket تونل | `/` و سپس ۱۵ تا ۵۱۱ حرف، رقم یا نویسهٔ `/`، `_` و `-`؛ هنگام نصب ساخته می‌شود و باید در دو طرف یکسان باشد. | مشترک |
| پورت inbound خارج | مقصد TCP اختصاصی و موجود روی `127.0.0.1` سرور خارج؛ تداخل پورت بررسی می‌شود. پورت ۸۰ برای چالش گواهی رزرو است. | مشترک |
| تعویض رمز مشترک تونل | token تصادفی تازه می‌سازد، بدون نمایش token قبلی؛ کد همگام‌سازی را فوراً به طرف مقابل برسانید. | مشترک |
| فایل گواهی و کلید خصوصی | مسیر مطلق فایل‌های موجود برای سایت Nginx خارج؛ گواهی باید معتبر، شامل دامنه و منطبق با کلید باشد. ایران در این نسخه سایت TLS عمومی ندارد. | محلی در خارج |

شمارهٔ پورت بین ۱ و ۶۵۵۳۵ است و محدودیت کلودفلر، مالکیت و listener هم بررسی می‌شود. پورت backend خصوصی یا مقصد تونل را برای ورودی عمومی استفاده نکنید. تغییر دامنهٔ خارج روی سرور خارج به فایل گواهی متناسب نیاز دارد؛ ویرایشگر پنهانی گواهی جایگزین صادر نمی‌کند و سایت‌های نامرتبط Nginx را بازنویسی نمی‌کند.

## MUX، Padding و منابع

| تنظیم | پیش‌فرض نصب تازه | محدودهٔ ویرایشگر |
|---|---|---|
| MUX | `on` | `on` یا `off`؛ مشترک |
| شدت Padding | `0.22`؛ داخل کد اتصال هم منتقل می‌شود | عدد متناهی از `0` تا `1`؛ مشترک |
| حداقل Session | `2`؛ اگر حداکثر `1` باشد، حداقل هم `1` است | `1` تا `64`، حداکثر به‌اندازهٔ سقف Session؛ فقط ایران |
| حداکثر Session | با MUX روشن `8`؛ با MUX خاموش پیشنهاد `32` | `1` تا `64`؛ فقط ایران |
| حداکثر Stream | مطابق جدول RAM پایین | `1` تا `65,536`؛ محلی |
| Stream در هر Session | `512` | `1` تا `512`؛ محلی |
| بودجهٔ کل حافظهٔ بافر | مطابق جدول RAM پایین | `16` تا `1,048,576` MiB؛ محلی |
| حافظهٔ نگه‌داری‌شدهٔ هر Stream | `2,048` KiB | `64` تا `1,048,576` KiB؛ محلی |
| مهلت نوشتن در تونل | `10s` | ثانیهٔ کامل از `1s` تا `60s`؛ محلی |
| مهلت نوشتن به کلاینت/مقصد | `0` | `0` یعنی غیرفعال؛ یا ثانیهٔ کامل از `1s` تا `300s`؛ محلی |

نصب‌کننده روی هر سرور جداگانه RAM گزارش‌شده در `/proc/meminfo` را بررسی می‌کند:

| RAM فیزیکی گزارش‌شده | بودجهٔ کل بافر | حداکثر Stream |
|---|---:|---:|
| کمتر از ۱٫۵ GiB | ۲۵۶ MiB | ۱٬۰۲۴ |
| از ۱٫۵ تا کمتر از ۴ GiB | ۵۱۲ MiB | ۲٬۰۴۸ |
| حداقل ۴ GiB، یا RAM تشخیص داده نشده | ۱٬۰۲۴ MiB | ۴٬۰۹۶ |

این اعداد پیش‌فرض نصب‌اند، نه تضمین ظرفیت. مقدار ذخیره‌شده را با `edit-show` ببینید. پیش‌فرض خود هسته، بدون تنظیم نصب‌کننده، ۵۱۲ MiB و ۵۱۲ Stream است؛ نصب‌کننده این دو مقدار را با جدول بالا جایگزین می‌کند.

بودجهٔ کل باید هم حافظهٔ یک Stream و هم حداقل ۶۴ KiB برای هر Stream تعریف‌شده را پوشش دهد. برای افزایش تعداد Stream شاید لازم باشد اول حافظه را بیشتر کنید؛ برای کاهش حافظه ممکن است ابتدا کاهش سقف Stream لازم شود. این محدودیت‌ها برای بافر دریافت و نوشتن‌های در حال انجام‌اند، **نه سقف کل RSS پردازش**؛ بخش‌های دیگر برنامه هم RAM مصرف می‌کنند.

با MUX روشن، چند اتصال کاربر Session مشترک دارند؛ pool از حداقل شروع می‌کند و زیر بار تا سقف تعیین‌شده رشد می‌کند. با MUX خاموش، هر اتصال کاربر Session اختصاصی می‌خواهد؛ سقف Session تعداد اتصال‌های اختصاصی هم‌زمان را محدود می‌کند و حداقل pool کاربردی ندارد. MUX خاموش معمولاً منابع بیشتری مصرف می‌کند.

شدت Padding درصد پهنای باند یا طول داده نیست؛ `0.22` به معنی ۲۲ درصد ترافیک اضافه نیست. احتمال فعال‌شدن و تعداد بایت‌ها مستقل از طول داده‌اند. `0` آن را خاموش می‌کند و زیر فشار صف، Padding داده کنار گذاشته می‌شود. افزایش شدت می‌تواند فقط سربار اضافه کند، بدون اینکه مسیر شما بهتر شود. پنجرهٔ کنترل جریان V1 همچنان ثابت و ۵۱۲ KiB است؛ کنترل تطبیقی RTT/افت نسخهٔ ۳٫۵ در این نسخه وجود ندارد.

## TLS، ECH و Fragment

این تنظیمات روی ایران تغییر می‌کنند؛ اتصال خروجی TLS از آنجا ساخته می‌شود:

| تنظیم | پیش‌فرض | انتخاب‌ها |
|---|---|---|
| پروفایل TLS | `chrome` | `chrome`، `firefox`، `ios` |
| حداقل TLS | `1.3` | `1.3` یا حالت سازگاری صریح `1.2` |
| ECH | `off` | `off` یا `strict` |
| تکه‌کردن ClientHello | `off` | `off` یا `hello` |
| اندازهٔ هر تکه | `100-200` بایت | `MIN-MAX` با شرط `16 ≤ MIN ≤ MAX ≤ 4096` |
| فاصلهٔ بین تکه‌ها | `1-3ms` | `MIN-MAXms` با شرط `0 ≤ MIN ≤ MAX ≤ 20` |
| بستهٔ CA مورد اعتماد | انتخاب‌شده هنگام نصب | مسیر مطلق فایل PEM موجود، بدون فاصله |

منوی نصب سه حالت دارد: ECH خاموش، ECH سخت‌گیرانه، یا ECH خاموش همراه Fragment آزمایشی. ECH سخت‌گیرانه به TLS 1.3 نیاز دارد و Fragment باید خاموش باشد؛ پیش از روشن‌کردن یکی، حالت متضاد را خاموش کنید. اگر دریافت تنظیمات ECH یا پذیرش آن توسط سرور شکست بخورد، اتصال strict قطع می‌شود؛ بازگشت پنهانی به TLS معمولی وجود ندارد.

برای دریافت تنظیمات ECH، رکورد HTTPS دامنه به‌ترتیب از این DoHها پرسیده می‌شود:

1. `https://cloudflare-dns.com/dns-query`
2. `https://dns.google/dns-query`

گزینهٔ پیشرفتهٔ هسته، `-ech-doh`، فهرست resolverها را با ویرگول می‌گیرد. نشانی باید HTTPS باشد و اطلاعات ورود یا fragment در URL نداشته باشد؛ redirect رد می‌شود. دنبال‌کردن alias و مهلت درخواست محدود است. منوی عادی ویرایشگر فیلدی برای resolver ندارد. این قابلیت فقط تنظیمات ECH را می‌گیرد و جای resolver سیستم‌عامل برای پیدا کردن آدرس عادی مقصد را نمی‌گیرد.

در نصب مدیریت‌شده، مقصد اتصال، SNI و WebSocket Host همگی دامنهٔ خارج‌اند. گزینهٔ جداگانه‌ای برای SNI دلخواه یا domain fronting در منو نیست. جست‌وجوی ECH هم از همان دامنه شروع می‌شود. وجود رکورد ECH به‌تنهایی پذیرش آن در handshake واقعی را ثابت نمی‌کند؛ با `godoftunctl doctor TUNNEL_ID` و سپس ترافیک واقعی کلاینت بررسی کنید. [راهنمای کلودفلر](CLOUDFLARE.fa.md) جزئیات سمت سرویس را توضیح می‌دهد.

Fragment نوشتن ClientHello را تکه‌تکه می‌کند؛ مسیر شبکه را تغییر نمی‌دهد، IP غیرقابل‌دسترسی را باز نمی‌کند و تضمین عبور از فیلترینگ نیست. پروفایل مرورگر ویژگی‌های handshake TLS/HTTP را تغییر می‌دهد، نه اینکه برنامه را به مرورگر تبدیل یا غیرقابل‌تشخیص بودنش را تضمین کند.

تنظیم `ca` ایران برای اعتبارسنجی **لبهٔ کلودفلر** است. تنظیم جداگانهٔ `local_ca` به اعتماد در بررسی محلی TLS سرور اصلی مربوط است، نه لبهٔ CDN. بستهٔ CA آفلاین پشتیبانی می‌شود؛ خاموش‌کردن اعتبارسنجی گواهی نه. هسته برای اتصال خروجی دقیقاً یکی از `-ca`، `-system-ca` یا `-fingerprint` را می‌پذیرد. نصب مدیریت‌شده از `-ca` استفاده می‌کند؛ دو حالت دیگر گزینهٔ اضافی منوی نصب نیستند.

## تغییر محلی و همگام‌سازی دو طرف

IPهای دو سرور، دامنه و پورت خارج، مسیر WebSocket، پورت مقصد، token، MUX، Padding و پورت‌های ورودی پیش‌فرض ایران مشترک‌اند. بقیهٔ تنظیمات منابع، اعتماد و گواهی محلی‌اند. تغییر نام نمایشی هم نیازی به همگام‌سازی ندارد.

برای تغییر مشترک:

1. روی یکی از دو طرف وارد `edit` شوید، فیلد را انتخاب و تغییر را تأیید کنید.
2. کد ویرایش محرمانهٔ خروجی را امن به طرف مقابل برسانید.
3. آنجا `sudo godoftunctl edit-apply TUNNEL_ID` را اجرا کنید، کد را در پرسش برنامه وارد و تغییر را بررسی کنید.
4. پیش از تغییر مشترک بعدی، دو طرف را بررسی کنید. تا وقتی تنظیمات متفاوت‌اند، قطعی موقت ممکن است.

کدها با HMAC احراز می‌شوند و به هویت جفت‌شدن، نقش طرف مقابل و مقدار قبلی وابسته‌اند. بعد از هفت روز منقضی می‌شوند و کد قدیمی یا مربوط به جفت دیگر پذیرفته نمی‌شود؛ ساعت دو سرور باید درست باشد. اولین همگام‌سازی IP/پورت ایران می‌تواند مشخصات خالی سمت خارج را پر کند. محتوای کد فقط کدگذاری شده و **رمزگذاری محرمانه نشده است**؛ کد تعویض token، رمز جدید را در خود دارد.

در این نسخه `apply-update` نام دیگر `edit-apply` است؛ قالب خام یا بدون امضای قدیمی و کد ۳.x را نمی‌پذیرد. کد نصب اولیهٔ `peer-code` هم قالب دیگری دارد و کد ویرایش نیست. اگر همگام‌سازی رد شد، وضعیت هر دو طرف و علت خطا را بررسی کنید؛ اعتبارسنجی را دور نزنید و تغییر مشترک نامرتبط دیگری روی مشکل قبلی اضافه نکنید.

## مشتری‌ها، پورت و سهمیهٔ تجمعی

مدیریت مشتری روی ایران انجام می‌شود:

```bash
sudo godoftunctl customers TUNNEL_ID
sudo godoftunctl usage TUNNEL_ID
```

نصب‌کننده حساب `default` را برای پورت‌های اولیهٔ ایران می‌سازد؛ سهمیهٔ خود این مشتری نامحدود است. سهمیهٔ جداگانهٔ کل تونل هم پیش‌فرض `0`، یعنی نامحدود دارد. هنگام افزودن مشتری، ۱۰۰ GB پیشنهاد می‌شود؛ قبل از قبول آن بررسی کنید. بعداً می‌توان به یک مشتری چند پورت داد که همگی از سهمیهٔ همان حساب مصرف کنند.

حسابداری بر اساس **پورت ورودی و حساب** است، نه UUID احرازشدهٔ Xray. آپلود و دانلود با هم جمع می‌شوند. بایت‌های سوکت کلاینت در ایران شمرده می‌شوند، بدون سربار فریم و Padding گادافتان؛ این عدد صورت‌حساب ISP/CDN یا فقط حجم فایل‌های برنامه نیست. کسی که ورودی شناخته‌شدهٔ دیگری را استفاده کند، از سهمیهٔ آن ورودی مصرف می‌کند. احراز هویت واقعی را در برنامهٔ مقصد تنظیم کنید و در صورت نیاز ورودی پیش‌فرض را محدود یا غیرفعال کنید.

هر GB برابر ۱٬۰۰۰٬۰۰۰٬۰۰۰ بایت است. مقدار اعشاری GB باید به تعداد صحیح بایت تبدیل شود. ابزار مدیریت سهمیهٔ غیرمنفی تا ۹٬۰۰۰٬۰۰۰ GB را می‌پذیرد. `0` یعنی نامحدود؛ بااین‌حال مشتری نامحدود همچنان زیر سقف محدود کل تونل است. رسیدن به هر سقف مربوط، ترافیک را می‌بندد و پایین‌آوردن سقف می‌تواند اتصال‌های موجود را قطع کند.

سهمیه‌ها سقف تجمعی‌اند، نه بستهٔ دوره‌ای. اگر ۳۰ GB مصرف شده و سقف را ۵۰ GB کنید، حدود ۲۰ GB باقی می‌ماند، نه ۵۰ GB تازه. تغییر نام تونل، پورت، فعال/غیرفعال‌کردن مشتری، restart و ارتقای معمول، مصرف را صفر نمی‌کنند. فرمان تمدید ماهانه، صفرکردن مصرف یا حذف مشتری وجود ندارد.

دفتر مصرف قبل از عبور داده، مقداری ظرفیت را روی دیسک رزرو می‌کند. پس از crash، رزرو استفاده‌نشده ممکن است محافظه‌کارانه مصرف‌شده حساب شود؛ حداکثر ۶۴ KiB برای هر حساب فعال. این کار جلوی کم‌شماری با restart را می‌گیرد؛ تطابق دقیق با صورت‌حساب را وعده ندهید. فایل مصرف گم‌شده یا خراب یک خطاست، نه مجوز ساختن دفتر مصرف صفر.

غیرفعال‌کردن مشتری دسترسی او را می‌بندد، اما شناسه، سهمیه، مصرف و ثبت پورت را نگه می‌دارد. فعال‌کردن فقط در صورت اجازهٔ سهمیه‌ها دسترسی را برمی‌گرداند. ذخیرهٔ تنظیم مشتری، تونل متوقف را روشن نمی‌کند. ویرایش پورت مصرف را حفظ می‌کند و پورت ثبت‌شده برای حساب یا تونل دیگر را، حتی اگر غیرفعال باشد، نمی‌پذیرد.

فایل خروجی مشتری فقط راهنمای endpoint است؛ اطلاعات ورود سرور، token جفت‌شدن یا تنظیم کامل احراز هویت Xray در آن نیست. مشخصات کلاینت را جداگانه بدهید. فایل قبلاً تحویل‌شده روی دستگاه مشتری خودکار تغییر نمی‌کند؛ پس از تغییر endpoint، خروجی تازه بگیرید و دوباره تحویل دهید. فهرست فرمان‌ها در [مدیریت](OPERATIONS.fa.md) و ملاحظات اشتراک‌گذاری در [امنیت](SECURITY.fa.md) آمده است.

## گزینه‌های پیشرفتهٔ هسته

برای گزینه‌های بیرون از منوی مدیریت، خروجی `godoftun -h` را ببینید. پیش‌فرض‌ها شامل `dial-timeout=10s`، `auth-timeout=10s`، `open-timeout=15s`، `session-idle=90s` و `probe-timeout=15s` هستند. محدودهٔ هسته برای dial/auth/write از ۱ تا ۶۰ ثانیه، open از ۱ تا ۱۲۰ ثانیه، session idle بیشتر از ۳۰ ثانیه تا یک ساعت و probe مقدار مثبت تا ۶۰ ثانیه است. نصب‌کننده آمار را هر پنج ثانیه ثبت می‌کند؛ پیش‌فرض خود هسته ثبت آمار را خاموش می‌گذارد.

محدودهٔ گزینهٔ خام و منو را یکی ندانید: هسته برای edge-write تا یک ساعت را می‌پذیرد، اما ویرایشگر تا ۳۰۰ ثانیه را پیشنهاد می‌کند. تغییر مستقیم فایل اجرا ممکن است دیگر از بررسی‌های مدیریت عبور نکند؛ برای استفادهٔ روزمره، همان ویرایشگر و مقادیر واقعی نمایش‌داده‌شده را مبنا بگیرید.
