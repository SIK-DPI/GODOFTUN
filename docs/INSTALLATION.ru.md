# Установка GODOFTUN V1.0.0

[English](INSTALLATION.md) · [فارسی](INSTALLATION.fa.md) · [简体中文](INSTALLATION.zh-CN.md) · [Главная](../README.ru.md)

Это руководство описывает установку одной пары узлов туннеля на двух серверах. Сначала настройте зарубежный сервер, затем сервер в Иране. Прежде чем заменять работающий сервис, проведите испытания на отдельных серверах.

## Схема соединения

```text
Client application
  -> Iran public IP and TCP entry port
  -> GODOFTUN origin
  -> foreign domain through Cloudflare WSS
  -> foreign Nginx and GODOFTUN egress
  -> dedicated application inbound on 127.0.0.1
```

Поддерживаемая схема фиксирована: Cloudflare Proxy ON для зарубежного домена, WSS и прямой вход по IP на стороне Ирана. Варианты с иранским доменом, Arvan, прямым соединением с зарубежным сервером, HTTP/2 или XHTTP не предлагаются. Это TCP-туннель, а не UDP-туннель и не VPN для всего устройства. Приложению Xray или приложению под управлением панели по-прежнему нужны собственные протокол, учётные данные и клиентская конфигурация. GODOFTUN не является продуктом Cloudflare Tunnel или `cloudflared`.

## Перед началом

- Нужны два сервера Ubuntu или Debian с systemd, доступом root через `sudo` и публичными IPv4-адресами. Установщик поддерживает amd64/x86_64 и arm64/aarch64, но не 32-битные системы. macOS не предназначена для установки сервиса.
- Подготовьте отдельный подконтрольный вам зарубежный поддомен, например `tunnel.example.com`, согласно [руководству по Cloudflare](CLOUDFLARE.ru.md). Это пример, а не работающая точка подключения; замените его своим именем.
- Создайте на зарубежном сервере отдельный вход приложения, прослушивающий `127.0.0.1` на свободном TCP-порту. Например, `18082` подходит только в том случае, если вы действительно создали вход на этом порту. Не изменяйте посторонний вход панели.
- Подготовьте сертификат и ключ исходного сервера либо обеспечьте прохождение HTTP-проверки Let's Encrypt, используемой установщиком. Одного сертификата пограничного узла недостаточно.
- Обеспечьте доступ к репозиториям пакетов для недостающих инструментов, API диапазонов IP Cloudflare для проверки проксирования и выбранной зарубежной HTTPS-точке подключения. Для ECH дополнительно требуется работающий поиск конфигурации через DNS-записи HTTPS. Копирование установщика без доступа к сети не устраняет эти сетевые требования.
- Синхронизируйте часы серверов и защитите существующий SSH-доступ от последствий изменения правил межсетевого экрана.

Установщик проверяет семейство ОС, но это не означает, что проверен каждый выпуск Ubuntu/Debian. См. [границы выполненного тестирования](../VALIDATION.md). Используйте поддерживаемые и обновлённые системные пакеты. Компилятор Go не нужен ни на одном из серверов.

## Проверка загруженных файлов

Распакуйте весь публичный ZIP-архив, перейдите в его папку `sik-dpi` и сохраните `SHA256SUMS` вместе с остальными файлами. На Linux выполните:

```bash
sha256sum -c SHA256SUMS
bash -n GODOFTUN-V1.0.0.sh
bash GODOFTUN-V1.0.0.sh preview
```

На macOS вместо первой команды используйте `shasum -a 256 -c SHA256SUMS`; просмотр меню также работает без установки. Для полной проверки контрольных сумм должны присутствовать все перечисленные файлы. Контрольная сумма выявляет изменения относительно списка, но не подтверждает подлинность самого списка, если его подменил злоумышленник. Получайте и файлы, и список из доверенного релиза владельца проекта.

Команда `preview` только показывает меню. Запуск без аргумента открывает интерактивное главное меню. Не выполняйте непроверенный загруженный файл напрямую через оболочку с повышенными правами.

## Сетевые порты

| Расположение | Требуемый доступ |
|---|---|
| Публичный интерфейс зарубежного сервера | Выбранные TCP-порты HTTPS, обычно 443; TCP 80 для устанавливаемого HTTP-сайта и автоматической проверки сертификата |
| Loopback зарубежного сервера | Отдельный вход приложения и закрытый WSS-бэкенд, выбранный установщиком; не открывайте их в публичную сеть |
| Публичный интерфейс сервера в Иране | Выбранные вами входные TCP-порты клиентов, например 21000 и 21001, если они свободны |
| Исходящие соединения из Ирана | DNS, HTTPS для предварительных проверок и выбранные HTTPS-порты зарубежного домена |
| Оба сервера | Существующий SSH-доступ и необходимые службы пакетов и синхронизации времени |

Публичные HTTPS-порты и клиентские порты в Иране — разные настройки; совпадать они не обязаны. Несколько иранских портов одного туннеля ведут к одной и той же настроенной цели приложения за рубежом. Для другой цели используйте другой именованный туннель с отдельными ресурсами. Если UFW уже включён, установщик добавляет необходимые TCP-правила; он не включает UFW и не настраивает межсетевой экран провайдера. Проверьте оба уровня. Не очищайте правила общего межсетевого экрана.

## Настройка зарубежного сервера

Сначала создайте вход приложения и завершите [подготовку DNS и сертификата](CLOUDFLARE.ru.md). Затем выполните:

```bash
sudo bash GODOFTUN-V1.0.0.sh foreign
```

Ответьте на вопросы установщика:

1. Выберите ID туннеля и понятное имя. ID состоит из 1–48 строчных букв, цифр и одиночных дефисов, начинается с буквы или цифры и не может содержать последовательные дефисы. Для нового туннеля используйте новый ID.
2. Выберите, включать ли MUX. Если у вас нет конкретной причины менять настройку, начните со значения по умолчанию; см. [настройку параметров](CONFIGURATION.ru.md).
3. Укажите зарубежный домен с включённым оранжевым облаком и настоящий IPv4-адрес зарубежного сервера. Публичный DNS должен возвращать адрес Cloudflare, а не адрес исходного сервера.
4. Укажите HTTPS-порты в порядке приоритета. Начните с `443`. Принимаются только перечисленные HTTPS-порты, совместимые с Cloudflare.
5. Укажите фактический порт отдельного входа приложения. Установщик проверит `127.0.0.1:PORT` и выберет другой свободный закрытый WSS-бэкенд.
6. Выберите браузерный TLS-профиль и интенсивность заполнения; значение по умолчанию — `0.22`.
7. Выберите автоматический Let's Encrypt либо существующие сертификат/ключ и локальный набор доверенных CA. Устраните ошибки предварительных проверок до подтверждения установки.

После запуска проверяются локальный HTTPS, переключение протокола на WebSocket с HMAC-аутентификацией (не полный обмен V1 «вызов–ответ») и путь через CDN. Держите созданный код сопряжения в секрете: он содержит параметры соединения и общий токен. Base64 не является шифрованием. Не размещайте код в публичных issue, снимках экрана или файлах GitHub.

## Настройка сервера в Иране

Передайте в Иран тот же проверенный установщик; в [руководстве по эксплуатации](OPERATIONS.ru.md) описана передача при недоступности GitHub. Выполните:

```bash
sudo bash GODOFTUN-V1.0.0.sh iran
```

1. Укажите, зарегистрирован ли уже другой туннель. Этот ответ не даёт разрешения на его замену.
2. Вставьте код сопряжения зарубежного сервера. Пустой ответ открывает ручной ввод; при первой установке используйте код, чтобы избежать несовпадения настроек.
3. По запросу выберите локальный ID/имя туннеля, затем укажите публичный IPv4-адрес сервера в Иране. Иранский домен не требуется.
4. Укажите один или несколько свободных клиентских портов через запятую, например `21000,21001`.
5. Выберите ограничение числа сессий и заполнение. MUX и транспорт импортируются с парного узла.
6. Выберите ECH OFF, строгий ECH ON либо ECH OFF с экспериментальным ClientHello Fragment. ECH и Fragment — альтернативы, а не совместный режим. См. [настройку параметров](CONFIGURATION.ru.md).
7. Установите суммарный лимит за весь период использования в десятичных GB. `0` означает отсутствие ограничения; входящий и исходящий трафик учитываются вместе.
8. Подтвердите установку после успешных предварительных проверок. Установщик проверяет транспортные сессии, но не учётные данные или полезную нагрузку вашего приложения.

При ошибке ввода или проверки прочитайте сообщение и повторите указанный шаг. Не обходите проверки отключением проверки сертификатов или переходом на неподдерживаемый транспорт.

## Подключение и проверка настоящего клиента

На каждом сервере найдите его ID туннеля:

```bash
sudo godoftunctl list
sudo godoftunctl status TUNNEL_ID
sudo godoftunctl doctor TUNNEL_ID
```

Замените `TUNNEL_ID` локальным ID из списка. На сервере в Иране команда `sudo godoftunctl info TUNNEL_ID` показывает сведения для подключения клиента. Не публикуйте этот вывод. В качестве адреса соединения клиента задайте IP сервера в Иране и назначенный входной порт; сохраните протокол, UUID/пароль и параметры безопасности уровня приложения, заданные для отдельного зарубежного входа. Если приложение использует TLS, его требования к SNI/сертификату сохраняются. Не путайте TLS приложения с внешним WSS TLS туннеля.

Перед предоставлением доступа пользователям проверьте на настоящем маршруте всё перечисленное:

- Реальный клиент с корректной аутентификацией передаёт и получает данные через каждый запланированный порт в Иране.
- Одновременные соединения и передача большого объёма данных работают без обрезанных ответов.
- После запланированного перезапуска сервиса новые соединения восстанавливаются; бесшовное сохранение существующих потоков не обещается.
- При выборе строгого ECH он действительно принимается; Fragment проверяется отдельно, без предположения, что он обязательно поможет.
- Тестовый клиент с лимитом достигает квоты и правильно блокируется; увеличение квоты не стирает уже учтённый расход.
- Диагностика, продление сертификата и доступ после перезагрузки сервера работают. Одной отметки процесса `active` или доступной обычной веб-страницы недостаточно.

Храните результаты тестов приватно и удаляйте учётные данные перед обращением за помощью. Далее изучите [эксплуатацию](OPERATIONS.ru.md), [устранение неполадок](TROUBLESHOOTING.ru.md) и [безопасность](SECURITY.ru.md).
