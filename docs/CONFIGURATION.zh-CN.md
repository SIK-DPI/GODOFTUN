GODOFTUN V1.0.0 只支持一种部署方式：境外域名开启 Cloudflare 代理并使用 WSS，伊朗侧通过 IP 和端口直接接入。编辑器不能切换到 Arvan、境外直连、伊朗侧域名、HTTP/2 或 XHTTP。它不会替你配置 Xray 客户端、入站认证、Cloudflare 账户或 DNS 记录。

## 打开设置编辑器

将 `TUNNEL_ID` 替换为 `list` 显示的隧道 ID。在需要查看或修改配置的服务器上运行：

```bash
sudo godoftunctl list
sudo godoftunctl edit-show TUNNEL_ID
sudo godoftunctl edit TUNNEL_ID
```

`edit-show` 显示保存的配置，不代表实时连接健康状况；token 会隐藏。编辑器先展示旧值和新值，再通过 `Apply? y/n` 请求确认，默认为 `n`。受影响且正在运行的服务可能会重启；已停止的服务保持停止。请使用菜单，不要手工重写 `run.sh` 或元数据：受管理的编辑器会一起检查相关限制、端口和对端设置。

## 连接与身份

| 设置 | 含义及限制 | 作用范围 |
|---|---|---|
| 隧道显示名称 | 可打印文本，最多 120 个 UTF-8 字节，不含 `=`。不更改内部隧道 ID 或配对身份。 | 本地 |
| 境外服务器 IPv4 | 用于元数据和检查的源站地址；伊朗连接器仍然连接代理域名。迁移服务器时需自行更新实际 DNS 源站。 | 两端共享 |
| 伊朗服务器 IPv4 | 提供给客户端的公网地址。客户端设备不会自动更新。 | 两端共享 |
| 境外域名 | 例如 `tunnel.example.com`，不含协议前缀、端口或路径。所有解析地址都必须通过编辑器的 Cloudflare 代理检查。 | 两端共享 |
| 境外 HTTPS 端口 | 从 `443,2053,2083,2087,2096,8443` 中选择，用逗号分隔且不重复；安装建议 `443`。 | 两端共享 |
| 伊朗接入端口 | 默认客户入口的直连 TCP 端口。其他客户账户有各自的端口设置。已占用或预留的端口会被拒绝。 | 元数据共享；监听器在伊朗改变 |
| 隧道 WebSocket 路径 | `/` 后接 15–511 个字母、数字、`/`、`_` 或 `-`。安装时生成，两端必须一致。 | 两端共享 |
| 境外 Xray 入站端口 | 境外服务器上已存在的专用 TCP 目标，地址为 `127.0.0.1`。编辑器检查冲突；80 端口保留给证书验证。 | 两端共享 |
| 轮换隧道共享密钥 | 生成新的随机 token，不显示旧 token。必须及时同步对端。 | 两端共享 |
| 证书及私钥文件 | 境外受管理 Nginx 站点所用文件的绝对路径。证书必须覆盖域名、在有效期内且匹配私钥。本版本伊朗侧没有公网 TLS 站点。 | 境外服务器本地 |

端口范围为 1–65535，同时受 Cloudflare、归属和监听状态检查约束。不要将隧道的私有后端端口或目标端口用于公网入口。修改境外域名时，境外服务器上必须有相匹配的证书文件；编辑器不会偷偷签发替代证书，也不会重写无关的 Nginx 站点。

## MUX、填充和资源限制

| 设置 | 新安装的默认值 | 编辑器允许范围 |
|---|---|---|
| MUX | `on` | `on` 或 `off`；两端共享 |
| 填充强度 | `0.22`，包含在配对码中 | `0`–`1` 的有限数值；两端共享 |
| 最少会话数 | `2`；最多会话数为 `1` 时取 `1` | `1`–`64`，不超过最多会话数；仅伊朗 |
| 最多会话数 | MUX 开启时 `8`；关闭时建议 `32` | `1`–`64`；仅伊朗 |
| 最多数据流数 | 由下方 RAM 档位决定 | `1`–`65,536`；本地 |
| 每个会话最多数据流数 | `512` | `1`–`512`；本地 |
| 全局保留缓冲区内存 | 由下方 RAM 档位决定 | `16`–`1,048,576` MiB；本地 |
| 每个数据流保留内存 | `2,048` KiB | `64`–`1,048,576` KiB；本地 |
| 隧道写入超时 | `10s` | 整秒 `1s`–`60s`；本地 |
| 客户端/目标写入超时 | `0` | `0` 表示禁用；否则整秒 `1s`–`300s`；本地 |

安装器根据各服务器自己的 `/proc/meminfo` 独立选择限制：

| 报告的物理 RAM | 全局保留缓冲区预算 | 最多数据流数 |
|---|---:|---:|
| 低于 1.5 GiB | 256 MiB | 1,024 |
| 至少 1.5 GiB，但低于 4 GiB | 512 MiB | 2,048 |
| 至少 4 GiB，或无法检测 RAM | 1,024 MiB | 4,096 |

这些是安装默认值，不是容量保证。请用 `edit-show` 查看实际保存值。独立核心程序的后备默认值为 512 MiB 和 512 个数据流；安装器会用 RAM 档位覆盖这两个值。

全局内存预算必须容纳单个数据流预算，并至少为每个配置的数据流提供 64 KiB。提高数据流上限可能需要先增加内存；降低内存可能需要先降低数据流上限。这些预算计算保留的接收缓冲区和正在执行的写入，**不是进程总 RSS 上限**。其他分配仍然消耗 RAM。

MUX 开启时，多条客户端连接共享隧道会话。连接池从最少会话数开始，并可在负载增加时增长到上限。MUX 关闭时，每条客户端连接需要专用会话；最多会话数限制并发专用承载连接的数量，最小池大小不起作用。关闭 MUX 通常需要更多资源。

填充强度不是带宽或载荷长度的百分比：`0.22` 不表示增加 22% 流量。启用概率和字节数都独立于载荷长度。`0` 关闭填充；队列有压力时会抑制数据填充。提高强度可能只增加开销，并不改善你的实际链路。本版本保留 V1 固定的 512 KiB 流量控制窗口，没有 3.5 的 RTT/丢包自适应窗口控制器。

## TLS、ECH 和 Fragment

这些连接设置在伊朗侧修改，因为出站 TLS 连接从那里建立：

| 设置 | 默认值 | 选项 |
|---|---|---|
| TLS 指纹配置 | `chrome` | `chrome`、`firefox`、`ios` |
| 最低 TLS 版本 | `1.3` | `1.3`，或明确选择 `1.2` 兼容模式 |
| ECH | `off` | `off`、`strict` |
| ClientHello 分片 | `off` | `off`、`hello` |
| 分片大小 | `100-200` 字节 | `MIN-MAX`，满足 `16 ≤ MIN ≤ MAX ≤ 4096` |
| 分片间隔 | `1-3ms` | `MIN-MAXms`，满足 `0 ≤ MIN ≤ MAX ≤ 20` |
| 可信 CA 证书包 | 安装时选定 | 已存在的 PEM 证书包绝对路径，不含空格 |

安装菜单提供 ECH 关闭、严格 ECH、或 ECH 关闭加实验性 Fragment。严格 ECH 要求 TLS 1.3，且 Fragment 必须关闭。启用其中一个前，先关闭冲突模式。如果 ECH 发现失败或服务器不接受 ECH，严格连接就会失败，不会静默回退到普通 TLS。

ECH 发现按以下顺序，通过 DoH 查询 HTTPS DNS 记录：

1. `https://cloudflare-dns.com/dns-query`
2. `https://dns.google/dns-query`

核心的高级参数 `-ech-doh` 接受用逗号分隔的解析器列表。地址必须使用 HTTPS，不含 URL 凭据或片段；HTTP 重定向会被拒绝。别名跟随次数和请求时间均有上限。普通编辑器没有解析器字段。此机制只获取 ECH 配置，不会替换操作系统用于普通目标地址解析的解析器。

受管理的连接器将境外域名用于连接目标、SNI 和 WebSocket Host。菜单没有独立的域名前置 SNI 选项。ECH 发现也从同一域名开始。找到 ECH 记录并不证明实际 TLS 握手会接受它；使用 `godoftunctl doctor TUNNEL_ID`，然后测试客户端流量。参见 [Cloudflare 配置](CLOUDFLARE.zh-CN.md)。

Fragment 只是拆分 ClientHello 的写入，不改变路由、不能让不可达 IP 变得可达，也不保证抵抗过滤。浏览器配置会改变 TLS/HTTP 握手特征，但不会把隧道变成浏览器，也不保证不可区分。

伊朗侧 `ca` 设置验证的是 **Cloudflare 边缘节点**。独立的 `local_ca` 设置用于本地源站 TLS 诊断信任，而非边缘节点。支持提供离线 CA 证书包，但不支持跳过证书验证。核心出站连接要求在 `-ca`、`-system-ca`、`-fingerprint` 中恰好选一个。受管理安装使用 `-ca`；指纹和系统证书库模式不是安装菜单的额外选项。

## 本地修改与两端同步

共享字段包括两台服务器的 IP、境外域名和端口、WebSocket 路径、目标端口、token、MUX、填充和伊朗默认接入端口。其他性能、信任和证书设置为本地设置。本地显示名称变化不需要同步对端。

修改共享设置时：

1. 在一端打开 `edit`，选择字段并确认修改。
2. 安全地将生成的机密编辑码传给匹配的对端。
3. 在对端运行 `sudo godoftunctl edit-apply TUNNEL_ID`，在提示中粘贴编辑码并检查修改内容。
4. 在进行下一项共享修改前，验证两端状态。设置不一致期间可能短暂中断。

编辑码通过 HMAC 认证，绑定配对身份和相反的角色，并检查旧值。有效期为七天；过时或错误对端的值会被拒绝，因此服务器时钟必须准确。首次同步伊朗 IP/接入端口时，可填补境外侧缺失的元数据。编辑码内容只是编码，**并未加密保密**；轮换 token 的编辑码包含新密钥。

本版本 `apply-update` 是 `edit-apply` 的别名，不接受旧的未签名/原始更新格式或 3.x 编辑码。`peer-code` 输出的安装配对码是另一种格式，不能作为编辑码使用。同步失败时，应检查两端并解决报告的不一致；不要绕过校验，也不要在未解决的问题上继续叠加无关共享修改。

## 客户、端口和累计配额

客户管理在伊朗侧运行：

```bash
sudo godoftunctl customers TUNNEL_ID
sudo godoftunctl usage TUNNEL_ID
```

安装器创建 `default` 账户，覆盖初始伊朗接入端口，客户配额不限。独立的隧道总配额默认为 `0`，同样不限。添加客户时建议额度为 100 GB，请确认后再接受。以后可以为一个客户分配多个接入端口，这些端口共用该账户的额度。

计量依据是**接入端口/账户**，不是经过认证的 Xray UUID。上传与下载相加。计量位置是伊朗客户端套接字，不包括 GODOFTUN 的帧和填充；它不是 ISP/CDN 计费表，也不只计算应用文件大小。能够使用另一个已知入口的人，可以消耗那个入口的额度。应在境外应用中配置真实客户端认证，并在适当时限制或停用默认入口。

`1 GB = 1,000,000,000 bytes`。小数 GB 必须能转换为整数个字节。管理工具接受非负额度，最大为 9,000,000 GB。`0` 表示不限，但不限额的客户仍受有限的隧道总额度约束。达到任一适用上限即阻止流量；降低上限可能关闭现有连接。

配额是累计使用上限，不是周期套餐。如果已使用 30 GB，将上限改为 50 GB 后，大约剩余 20 GB，而不是额外获得 50 GB。重命名隧道、修改端口、停用/启用客户、重启和正常升级都不会清零用量。没有按月续期、清零用量或删除客户的命令。

账本会在允许流量通过前，先将字节预留持久化。发生崩溃后，未使用的预留可能被保守地记作已用量，每个活跃账户最多多计 64 KiB。这用于避免重启后的少计，不应承诺与外部账单完全一致。账本缺失或无效属于错误，不能因此初始化一个空账本。

停用账户会关闭其访问，但保留 ID、配额、计数器和端口登记。重新启用后，仍只有在配额允许时才能访问。保存客户设置不会启动已停止的隧道。修改客户端口保留用量，并拒绝其他账户或隧道已登记的端口，即使对应入口已停用。

客户导出文件只有端点说明，不含服务器登录信息、隧道配对 token 或完整 Xray 凭据。请单独提供正确的客户端凭据。已发给客户的文件不会在设备上自动更新；端点变化后应重新导出和发送。完整命令见[运维](OPERATIONS.zh-CN.md)，分享文件和诊断前请阅读[安全](SECURITY.zh-CN.md)。

## 高级运行参数

受管理编辑器之外的参数，以已安装核心的 `godoftun -h` 为准。默认值包括 `dial-timeout=10s`、`auth-timeout=10s`、`open-timeout=15s`、`session-idle=90s` 和 `probe-timeout=15s`。核心允许 dial/auth/write 为 1–60 秒，open 为 1–120 秒，会话空闲超时大于 30 秒且不超过一小时，probe 超时为正值且不超过 60 秒。安装器每五秒记录一次统计；原始核心默认关闭统计日志。

不要混淆原始参数和编辑器范围。例如核心允许 edge-write 超时最多一小时，而受管理编辑器最多提供 300 秒。直接修改启动文件可能导致受管理检查失败。日常修改请使用编辑器，并以其显示的实际值为准。
