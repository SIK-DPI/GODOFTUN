# Настройка зарубежного домена Cloudflare

[English](CLOUDFLARE.md) · [فارسی](CLOUDFLARE.fa.md) · [简体中文](CLOUDFLARE.zh-CN.md) · [Главная](../README.ru.md)

Используйте отдельный поддомен для GODOFTUN V1.0.0. Эти параметры задаются в вашем аккаунте Cloudflare; установщик не создаёт DNS-записи и не меняет настройки аккаунта. Названия и расположение пунктов панели могут меняться. Ссылки на официальную документацию проверены 2026-10-01.

## DNS

В DNS-записях зоны создайте A-запись выбранного поддомена, указывающую на публичный IPv4-адрес зарубежного сервера. Установите статус проксирования Proxied — оранжевое облако. При включённом проксировании DNS возвращает адреса Cloudflare вместо адреса сервера. [Статус проксирования](https://developers.cloudflare.com/dns/proxy-status/)

Для первого развёртывания используйте один выбранный исходный сервер. Не добавляйте к этому имени постороннюю AAAA-запись, балансировщик нагрузки или маршрут Worker. Перед изменениями проверьте существующие записи. Для Ирана DNS-запись не нужна.

На обоих серверах замените пример домена своим и проверьте ответы:

```bash
getent ahostsv4 tunnel.example.com
getent ahostsv6 tunnel.example.com
```

GODOFTUN сверяет полученные адреса с официальными диапазонами Cloudflare из `https://api.cloudflare.com/client/v4/ips`. Смешанный ответ, прямой адрес исходного сервера, адрес не из Cloudflare или непроверенный ответ отклоняются. Если API недоступен, восстановите доступ и повторите попытку; в этой версии нет автономного обхода данной проверки.

## HTTPS-порты и WebSockets

Начните с TCP 443. GODOFTUN принимает HTTPS-порты `443,2053,2083,2087,2096,8443`, соответствующие поддерживаемым портам прокси Cloudflare. [Сетевые порты](https://developers.cloudflare.com/fundamentals/reference/network-ports/)

В настройках Network включите WebSockets. На начальный запрос переключения протокола могут влиять правила безопасности, а Cloudflare может закрывать длительные соединения. [WebSockets](https://developers.cloudflare.com/network/websockets/)

Для этого развёртывания сохраняйте Host/SNI домена и закрытый путь. Не применяйте к WSS-запросу с аутентификацией перенаправления, кэширование, интерактивные проверки браузера или изменение заголовков. Если правило безопасности блокирует запрос, изучите конкретное событие и создайте минимально необходимое и обоснованное исключение для имени/пути вашего туннеля. Не отключайте защиту всей зоны. GODOFTUN формирует маршрут переключения протокола в Nginx; ручная замена этого маршрута может нарушить аутентификацию.

## Две отдельные проверки сертификатов

Коннектор в Иране проверяет публичный сертификат пограничного узла. Nginx на зарубежном сервере нужен отдельный сертификат исходного сервера. В настройках SSL/TLS выберите Full (strict) и используйте действующий сертификат исходного сервера, покрывающий нужное имя и подписанный общедоверенным CA или Cloudflare Origin CA. Успешная проверка с локальным набором CA сама по себе не означает, что Cloudflare доверяет сертификату. [Режим Full strict](https://developers.cloudflare.com/ssl/origin-configuration/ssl-modes/full-strict/)

Установщик предлагает два способа работы с сертификатом исходного сервера:

| Способ | Что нужно предоставить |
|---|---|
| Автоматический Let's Encrypt | Адрес электронной почты и доступный путь HTTP-проверки; установщик запрашивает сертификат через Certbot |
| Существующий сертификат | Абсолютные пути без пробелов к цепочке сертификатов и незашифрованному закрытому ключу, а также набор CA для локальной проверки исходного сервера |

Локальная проверка проверяет имя узла, соответствие ключа и срок действия; предоставленный сертификат отклоняется, если до окончания действия осталось менее 24 часов. Не вставляйте содержимое закрытых ключей в ответы терминала: указывайте пути к файлам, хранящимся приватно.

Для сертификата Cloudflare Origin CA используйте соответствующий набор корневых CA при локальных проверках исходного сервера. Origin CA не входит в обычную систему доверия браузеров. [Origin CA](https://developers.cloudflare.com/ssl/origin-configuration/origin-ca/)

Коннектор в Иране по-прежнему использует хранилище доверия публичного пограничного узла, а не ваш набор Origin CA. В редакторе предусмотрены отдельные поля для локального CA исходного сервера и CA пограничного узла. Не устраняйте ошибки сертификата отключением проверки.

## Первоначальная выдача и продление

Автоматическая выдача использует HTTP-webroot зарубежного сервера по пути `/.well-known/acme-challenge/`. TCP 80 должен быть доступен. Убедитесь, что этот путь ведёт к выбранному исходному серверу без интерактивной проверки, кэширования или перенаправления на ещё не существующий HTTPS-слушатель. Сохраняйте Proxy ON. Любое временное исключение для маршрутизации/перенаправления ограничьте путём проверки и до завершения установки убедитесь, что обычный HTTPS в режиме Full (strict) работает.

Установщик может настроить продление через Certbot и управляемый обработчик перезагрузки конфигурации Nginx. Ответственность за существующие сертификаты, не управляемые Certbot, остаётся за вами. Следите за сроком действия и проверьте механизм продления во время приёмочных испытаний на Linux. Успех при установке не доказывает, что будущее продление будет успешным.

Если правила аккаунта не позволяют выполнить первоначальную HTTP-проверку без ослабления защиты посторонних сервисов, выберите уже выданный сертификат. Установщик не предоставляет процедуру DNS-проверки через API и не запрашивает ваш API-токен Cloudflare.

## ECH

Cloudflare описывает ECH в документации по пограничным сертификатам SSL/TLS. Доступность и настройки зависят от зоны; ECH скрывает имя узла во внутреннем ClientHello от промежуточных участников, но не от Cloudflare. [Настройка ECH](https://developers.cloudflare.com/ssl/edge-certificates/ech/)

Строгому режиму ECH в GODOFTUN нужны опубликованная в HTTPS-записи конфигурация ECH, доступный механизм её обнаружения и TLS 1.3-рукопожатие, которое действительно её принимает. Одного включённого параметра в панели недостаточно. Используйте результаты настоящего соединения GODOFTUN и Doctor; посещение сайта или обычная TLS-проверка не воспроизводят его рукопожатие. См. [настройки ECH и Fragment](CONFIGURATION.ru.md).

## Проверка всего пути

После установки зарубежного узла обычный HTTPS-запрос к корню домена должен открывать созданный нейтральный сайт. Надпись «All systems operational» на нём — статический текст страницы-прикрытия, а не результат проверки текущего состояния. Затем завершите установку в Иране и проверьте реальную передачу данных приложения по [руководству по установке](INSTALLATION.ru.md).

Защищайте адрес исходного сервера и целевое приложение. Cloudflare завершает TLS-соединение на участке WSS, поэтому эта схема не обеспечивает сквозную конфиденциальность от Cloudflare; необходимое сквозное шифрование должно предоставлять приложение внутри туннеля. Перед распространением клиентского доступа прочитайте [руководство по безопасности](SECURITY.ru.md).
